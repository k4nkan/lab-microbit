# micro:bit 学習実験用 問題サイト

問題提示・進行管理・操作ログ収集を行うローカル実験用サイトです。MakeCodeのEdit Loggerのログも、このAPIへ自動で集まります。

## セットアップ

```bash
cd microbit-research-website
make setup
```

必要に応じて `frontend/.env.example` を `frontend/.env` にコピーし、APIとMakeCodeのURLを変更します。

## 起動

フロントエンドとバックエンドをまとめて起動します。

```bash
make dev
```

起動完了後、学習者画面 `http://localhost:5173` がブラウザで自動的に開きます。

個別に起動する場合は、ターミナルを2つ使います。

```bash
make backend
```

```bash
make frontend
```

- 学習者画面: http://localhost:5173
- 管理画面: http://localhost:5173/admin
- API仕様: http://localhost:8000/docs
- ログDB: `backend/data/research.db`
- 自動保存JSON: `backend/data/exports/sessions/<開始日時>_<参加者ID>/`

フロントエンドだけでも「開始」ボタンから進行できます。その場合、操作ログはブラウザのLocalStorageだけに保存され、終了時にJSONとしてダウンロードされます。

同一LANから使う場合は、`frontend/.env` の `VITE_API_URL` をバックエンドPCのIPに変更し、バックエンド起動時の `CORS_ORIGINS` にフロントのURLを追加してください。認証を持たない実験用構成のため、信頼できるLAN内だけで利用してください。Edit LoggerはPCごとに `localhost:8000` へ送るため、ロガーとの自動連携はAPIと同じPCで実験する場合に限られます。

## 実験の流れ

教材は3つのフェーズで構成されています（`frontend/src/tasks.ts`）。

1. チュートリアル：MakeCodeとEdit Loggerの準備、アイコン表示、ボタン
2. ゲーム制作：傾けてボールを動かし、ゴールでハートを出し、Aボタンでやり直すゲームを順番に作る
3. 自由アレンジ：音、ランダムなゴール、壁、タイム、スコア、障害物などの例を見ながら自由に工夫する

## データの自動保存

1. 学習者画面で参加者IDを入力して「開始」を押します（空欄なら `P-XXXX` を自動で付けます）。新しく開始すると、終わっていない前の実験は `abandoned` として閉じられます。
2. MakeCodeでEdit Loggerを一度開きます。ロガーは `GET /api/experiment/current` で現在の実験を検出し、記録を自動で開始・停止します。IDの入力は不要です。ロガーはこの問い合わせで自分の状態も報告し、問題サイトのヘッダーに「MakeCode記録: 記録中 / 停止中 / 未接続」と表示されます。記録中でない間は警告が出て、T1は「完了して次へ」を押せません。
3. 問題サイトのイベントとロガーのイベントは、受信するたびに実験フォルダの `*.jsonl` へ追記されます。
4. 「ここまでのログを保存」または実験終了時に、整形済みの `session.json`・`problem-events.json`・`makecode-events.json`・`merged.json` を書き出します。

ロガーのイベントは、イベントの時刻がどの実験の開始〜終了（＋60秒）に入るかで紐付けます。どの実験にも入らないものは `exports/unassigned/` に保存されます。各イベントは `eventId` を持ち、再送されても重複しません。

送れなかったイベントは、問題サイトとロガーのどちらもブラウザ内に残し、再接続時に自動で再送します。ロガー画面右上に `サーバー未送信 N件` と表示されている間は、まだ送信が終わっていません。

自動保存に失敗した場合は、Edit LoggerのExport JSONで書き出したファイルを、管理画面の「ロガーJSONを手動で取り込む」から取り込めます。

## ログ上の制約

- ステップ完了は学習者の自己申告で、正解判定ではありません。
- ヒント・解答を開いた記録は、内容を理解したことを意味しません。
- MakeCodeロガーのコード変更は定期スナップショットで、個々のブロック操作ではありません。
- `boot` は手動リセットでも発生し、書き込み操作と常に一致するわけではありません。
- 統合ログは両ログの絶対時刻で整列します。PCの時計がずれている場合、その差は自動補正されません。実験前に各PCの時刻同期を確認してください。
